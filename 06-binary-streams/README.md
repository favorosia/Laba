# Практическая работа №4: байтовые потоки Java

Решены **все 50 вариантов** из «ТМП - Практическая работа 3-4.pdf». На обложке PDF указана работа №4. У каждого варианта собственный пакет `task01` ... `task50`, класс с точным именем из условия и `Demo.java` с тестовыми данными и проверкой результата.

## 1. Установить Java на macOS

Нужен **JDK 17 или новее** с командами `java`, `javac`, `jar`. Maven, Gradle и сторонние Java-библиотеки не нужны.

Если JDK ещё нет: скачай Temurin 17 **JDK** для macOS с https://adoptium.net/temurin/releases/?version=17 и установи `.pkg`. Для Apple Silicon (M1/M2/M3/M4) выбирай **aarch64**, для Intel — **x64**. JRE недостаточно: он не содержит компилятора.

В Терминале:

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
export PATH="$JAVA_HOME/bin:$PATH"
java -version
javac -version
jar --version
```

Если установлен только более новый JDK, используй `export JAVA_HOME=$(/usr/libexec/java_home)` без `-v 17`. Переменные действуют в текущем окне; при необходимости добавь эти две строки export в `~/.zshrc`.

## 2. Запустить полученный вариант

Перейди в папку проекта. Например, если распаковала архив в Downloads:

```bash
cd "$HOME/Downloads/06-binary-streams"
bash run.sh 7
```

Вместо `7` укажи номер из задания. Поддерживается и `07`. Скрипт соберёт **только этот вариант** и запустит его. Без аргумента `bash run.sh` спросит номер. `chmod +x` не требуется: скрипты вызываются через bash.

Демонстрация создаёт входные бинарные файлы, вызывает алгоритм, показывает результат и проверяет его. При успехе печатает `Проверка: OK`. Данные остаются в `data/task07/`. Повторный запуск перезаписывает демонстрационные файлы этого варианта.

## 3. Собрать отдельно от запуска

```bash
bash build.sh 7
java -Dfile.encoding=UTF-8 -jar build/variant-07.jar
```

Этот JAR сразу запускает №7. Собрать все варианты в один JAR:

```bash
bash build.sh all
java -Dfile.encoding=UTF-8 -jar build/practice-04-all.jar 7
```

Для меню запусти тот же JAR без номера. Для всех 50 демонстраций:

```bash
bash run.sh all
```

Скрипты переходят в папку проекта сами, поэтому их можно вызывать и из другой папки. При прямом запуске `java` файлы `data/` создаются относительно текущей папки Терминала.

## 4. Шаблон ручной сборки одного варианта

В папке проекта меняется только `variant`. Здесь номер обязательно двузначный:

```bash
variant=07
mkdir -p "build/manual-$variant"
javac -encoding UTF-8 --release 17 \
  -d "build/manual-$variant" \
  src/common/Data.java "src/task$variant/"*.java
java -Dfile.encoding=UTF-8 -cp "build/manual-$variant" "task$variant.Demo"
```

Упаковка в исполняемый JAR:

```bash
jar --create --file "build/manual-$variant.jar" \
  --main-class "task$variant.Demo" -C "build/manual-$variant" .
java -Dfile.encoding=UTF-8 -jar "build/manual-$variant.jar"
```

- `-d` — папка с результатом компиляции, файлами `.class`.
- `-cp` — где JVM ищет классы.
- `task07.Demo` — полное имя запускаемого класса с пакетом.
- `--release 17` — совместимость с Java 17 при сборке более новым JDK.
- `-encoding UTF-8` — кодировка исходников, `-Dfile.encoding=UTF-8` — кодировка исполнения.

## 5. Как изменить данные и объяснить решение

1. Открой `src/taskXX/Demo.java` и основной класс в той же папке.
2. Измени значения в `Data.bytes/ints/doubles` или в массиве тестовых данных и параметры конструктора.
3. Обнови ожидаемый результат в `Data.expect/expectInts/expectDoubles`. Иначе проверка закономерно не совпадёт с новыми данными. Для массивов проверяется совпадение исходного и восстановленного массива.
4. Запусти `bash run.sh XX` ещё раз.

Чтобы обработать существующий файл, поменяй `Path input` в Demo и убери генерацию этого входа. Обнови или убери демонстрационную проверку и подбери вывод под формат своего файла. Методы решений принимают `Path`, их можно вызывать из собственного `main`.

Для переноса одного варианта нужны его папка `src/taskXX` и `src/common/Data.java`. У части вариантов `Data.count` проверяет длину записей; в остальных общий класс нужен только демонстрации. Исходники других вариантов не нужны.

## 6. Структура проекта

```text
src/
  Main.java                       общий выбор номера
  common/Data.java                данные, вывод, проверки формата и результата
  task01/ChunkFileCopier.java      решение №1
  task01/Demo.java                 демонстрация №1
  ...
  task29/BooleanArrayReader.java   дополнительный класс по условию №29
  ...
  task50/NormalizedHistogramWriter.java
  task50/Demo.java
tests/EdgeCases.java               проверки граничных случаев
build.sh                          сборка выбранного варианта или всех
run.sh                            сборка и запуск
test.sh                          все демонстрации + граничные проверки
build/                            созданные классы и JAR
data/                             созданные бинарные файлы
```

В решениях используются байтовые `FileInputStream`, `FileOutputStream`, `DataInputStream`, `DataOutputStream`. Из `java.nio` — только `Path` и `Files`. Нет символьных Reader/Writer, RandomAccessFile, каналов и сериализации объектов. `Arrays` используется для вывода и сравнения в демонстрациях; Общее меню Main использует обычный switch для запуска выбранного номера. Ввод номера читается через байтовый `System.in`.

`try-with-resources` закрывает потоки автоматически, даже при ошибке. `IOException` означает ошибку файла или формата, `IllegalArgumentException` — неверный параметр. Входы и выходы должны обозначать **разные файлы**; выход перезаписывается. Родительская папка выхода должна существовать — Demo создаёт её заранее. Входной файл не должен изменяться во время обработки.

## 7. Форматы и важные детали условия

### Байты и числа

`InputStream.read()` возвращает **int 0..255**, `-1` означает конец потока. Поэтому №13/18/21/26 работают с беззнаковыми значениями. PDF не уточняет знаковость в №13/18/26; выбран единый подход 0..255. №48 специально работает со **знаковым byte -128..127**, как требует условие.

`write(int)` сохраняет младшие 8 бит, поэтому запись `-1` создаёт байт 255, а не признак конца файла.

| Тип | Размер | Запись и чтение |
|---|---|---|
| int | 4 байта | writeInt/readInt |
| double | 8 байтов | writeDouble/readDouble |
| float | 4 байта | writeFloat/readFloat |
| short | 2 байта | writeShort/readShort |
| char | 2 байта | writeChar/readChar |
| boolean | 1 байт | writeBoolean/readBoolean |

Data-потоки используют big-endian. Текстовый файл с `123` — не файл с `writeInt(123)`. В №9/12/23/28/33/34 последовательности int **без заголовка**. В №22 перед массивом записывается его длина. №30 читает boolean **без длины**, №29 содержит длину и boolean.

### Отдельные варианты

- **№7/47:** демонстрируются и шифрование, и восстановление исходных данных.
- **№16/18:** ограничение 1024 байта проверяется. Для сортировки используется простой подсчёт частот.
- **№20:** серия имеет формат `byte value + int count`, всего 5 байтов. Demo читает пары и вызывает `decode`. RLE может увеличивать размер файла с короткими сериями.
- **№21:** в PDF конфликт: написано «абсолютную разницу», но формула `b[i] - b[i-1]` без модуля. Реализован `out.write((byte)Math.abs(current-previous));`. Если преподаватель требует буквально формулу, замени на `out.write((byte)(current-previous));` и обнови ожидаемый результат Demo. Для пустого входа результат пустой, для непустого — на байт короче.
- **№27:** вход создан через writeChar, это не UTF-8. Меняется только латиница a..z.
- **№32:** N >= 0; сдвиг больше длины приводится по модулю длины. Файл читается в память, как требует условие.
- **№33:** входы уже отсортированы. Алгоритм слияния не сортирует их заново и не загружает все int в память.
- **№35:** прямоугольная матрица, заголовок `int rows + int columns`, элементы построчно. Пустой двумерный массив записывается как 0x0.
- **№37/38:** файлы обязаны иметь одинаковые размеры; иначе ошибка.
- **№40:** допустимы позиции 0..размер файла включительно; последняя означает вставку в конец.
- **№41/42:** start..end включительно, позиции с нуля; диапазон должен целиком лежать внутри входа.
- **№43:** непересекающиеся совпадения. Для `[1,1,1,1,1]` и `[1,1]` результат 2. Пустой образец запрещён. Память O(длина образца), время O(размер файла * длина образца): выбран простой алгоритм окна.
- **№44:** при равенстве длин выбирается первая серия. Для пустого входа `(int 0, byte 0)`, значение байта условное.
- **№45:** Java modified UTF-8. Одна строка ограничена 65535 байтами в этой кодировке; слишком длинная вызывает исключение.
- **№46:** нумерация с 1; при N=1 удаляются все байты.
- **№47:** любой int-сдвиг, включая отрицательный, приводится по модулю 256.
- **№48:** `abs(-128)` даёт int 128; после приведения к byte это снова -128.
- **№49:** ровно N файлов, размеры отличаются не больше чем на 1; при 7 байтах и N=3 размеры 3,2,2. При N больше длины последние части пустые. Имена `part-001.bin`, ... Старые лишние части от запуска с большим N не удаляются автоматически.
- **№50:** ровно 256 float (1024 байта). Для пустого входа явно принято записывать 256 нулей. Для непустого сумма вероятностей приблизительно 1 из-за округления float.

### Пустые и повреждённые файлы

Обычные преобразования пустых файлов дают пустой выход. Счётчики и сумма дают 0. №10/13/24 сообщают об ошибке: у пустого набора нет среднего и экстремумов. №22/29/35/45 умеют сохранять пустые массивы. №49 создаёт N пустых частей.

Обрезанные int/double/char/short отвергаются проверкой длины записи. В №12/23 переполнение результата int соответствует обычной арифметике Java — сохраняются младшие 32 бита. Счётчики int используют Math.addExact; переполнение сообщается исключением.
